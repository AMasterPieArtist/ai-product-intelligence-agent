# 场景选型建议的产品设计

用户问题：原矩阵显示每条结果，却仍需要PM自己归纳“哪个需求优先哪套配置”。

本次新增输出以六类业务场景为入口，支持四种用户需求切换。每个场景先给优先建议和适用限制，再展开具体任务，最后展示复核依据。原96行矩阵继续承担逐条对照作用。

## 建议是如何产生的

1. 预定组合没有完成或没有复核：暂不选型。
2. 场景内存在双方明确失败的子项：提示两套均需补齐，不能用平均比例覆盖它。
3. 两边所选需求全部通过：并列满足，成本/维护方面留待测量。
4. 一边全部通过：优先该配置；对方只是无法确定时，表述为证据更充分，不当作失败。
5. 双方均有缺口：只有明确配对差异单向时才给有条件建议；交叉优劣不强行排序。
6. 候选存在明确来源错误：先核查来源再确认选型。

资料核查需求要求任务和来源都通过；其他Persona使用任务复核，但候选的明确来源错误仍会提示风险。因此“满足需求数”不一定等于原任务通过数。原始192条标签未改变。

这些规则是目前可解释的决策启发式。六类场景是展示层的业务分组，不是新增实验，也不是经过真实PM验证的权重模型。场景内任务默认都属于待满足范围；生产选型仍需要明确哪些需求是硬门槛，并补测真实数据、成本、安全与维护约束。

## 验证

场景规则包含 7 项离线测试，覆盖共同失败、无法确定、资料核查双条件与来源风险等分支。发布版整体验证见[验证说明](validation.md)。历史标签与材料未改变，本次未新增线上调用。
